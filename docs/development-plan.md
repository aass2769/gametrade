# GameTrade 개발 계획과 README 구성

상태: 설계안 (구현 전)  
기준일: 2026-10-14

구현은 P0를 끝낸 뒤에 P1으로 넘어간다. 각 단계의 완료 조건은 그 단계 산출물이 브라우저 또는 DB에서 확인되는 상태다. 파일을 만들기만 한 상태는 완료가 아니다.

## 1. 필수 단계와 선택 단계

필수 단계는 P0와, P0를 포트폴리오로 설명하기 위한 README의 최소 항목이다.

| 구분 | 단계 |
| --- | --- |
| 필수 | 1 환경, 2 구조, 3 DB, 4 레이아웃, 5 목록·상세, 6 회원, 7 등록·수정·삭제·내 판매 목록, 8 권한, 9 검색·필터, 10 상태, 11 보안 검토, 12 P0 테스트 |
| 선택 | 13 정렬, 15 페이지네이션, 16 반응형, README의 화면 캡처와 개선 아이디어 보강 |

요청서의 순서는 목록·등록을 회원 기능보다 앞에 둔다. 그 순서에는 의존성 문제가 있다. 상품은 `user_id`가 필수다. 회원 없이 등록을 먼저 만들면 임시 사용자 번호를 하드코딩하게 된다. C5로 남기고, 이 문서의 단계 번호는 아래 권장 순서를 따른다.

권장 순서의 핵심은 공개 조회 다음에 회원가입·로그인을 만들고, 그 다음 등록·수정·삭제를 만드는 것이다. 조회는 시드 데이터로 회원 화면 없이 확인할 수 있다.

## 2. 구현 단계

### 1단계. 개발 환경 확인

필수.

할 일:

- `php -v`, `mysql --version` 또는 MariaDB 버전, `httpd -v`를 확인한다.
- Apache와 MariaDB를 XAMPP에서 실행한다.
- PHP가 8.1 미만인지, CHECK 제약을 강제하는 DB인지 적는다.
- `pdo_mysql`이 켜져 있는지 확인한다.

완료 조건:

- 브라우저에서 Apache 기본 페이지 또는 이후 단계의 `public` 페이지가 열린다.
- MySQL 클라이언트에서 `SELECT VERSION();`이 성공한다.
- 버전 메모를 README 초안에 적을 수 있다.

### 2단계. 프로젝트 기본 구조

필수.

할 일:

- `docs/architecture.md`의 디렉터리를 만든다.
- `config.example.php`, 루트 `.htaccess`, `public` 가상 호스트 또는 링크를 만든다.
- `.gitignore`에 `config/config.php`와 `storage/logs/*.log`를 넣는다.
- Git 저장소가 없으면 `git init` 한다. 이 설계 단계에서는 하지 않았다.
- 진입 파일은 빈 레이아웃만 출력해도 된다.

완료 조건:

- `http`로 `public/index.php`가 열린다.
- `http`로 `config/config.php`와 `src/db.php`가 열리지 않는다.
- 예시 설정 파일에는 비밀번호가 없다.

### 3단계. 데이터베이스 생성과 연결

필수.

할 일:

- `docs/database-design.md`의 SQL로 `sql/schema.sql`을 만들고 적용한다.
- 가상 게임 시드와, 로컬에서 생성한 비밀번호 해시를 가진 샘플 회원 2명, 상태별 상품을 `sql/seed.sql`에 넣는다.
- DML만 가능한 DB 사용자를 만든다.
- `config/config.php`와 `src/db.php`를 연결한다.
- 연결 실패 메시지를 한 번 확인한 뒤 설정을 되돌린다.

완료 조건:

- `SHOW TABLES;`에 `users`, `games`, `game_servers`, `items`가 있다.
- 임시 진입 파일이나 이후 목록 페이지가 시드 상품을 읽는다.
- 잘못된 비밀번호일 때 화면에 계정 정보가 보이지 않는다.
- `config.php`가 Git 추적 대상이 아니다.

### 4단계. 공통 레이아웃

필수.

할 일:

- `bootstrap.php`, `helpers.php`, `header.php`, `footer.php`, `style.css`를 만든다.
- 헤더는 아직 로그인 전이므로 로그인, 회원가입 링크만 있어도 된다. 세션 연동은 6단계에서 헤더에 연결한다.
- 플래시 메시지 영역을 비워 둔다.

완료 조건:

- 목록 자리를 포함한 페이지가 공통 상단과 하단을 쓴다.
- 한글이 깨지지 않는다.
- 페이지 소스에 UTF-8이 있다.

### 5단계. 목록과 상세

필수. 공개 기능이라 로그인보다 먼저 해도 된다.

할 일:

- `searchItems()`의 필터 없는 목록과 `findItem()`을 구현한다.
- `index.php`, `item.php`를 연결한다.
- 상태 한글 라벨과 가격 표시를 적용한다.
- 없는 id의 404를 적용한다.
- 출력은 `e()`를 사용한다.

완료 조건:

- 비로그인으로 시드 목록과 상세가 보인다.
- 상세에 판매자 아이디, 게임, 서버, 설명, 상태가 있다.
- 없는 id에 SQL 오류가 보이지 않는다.
- 이 단계에서는 수정 버튼을 아직 보여 주지 않아도 된다. 작성자 버튼은 8단계다.

### 6단계. 회원가입과 로그인

필수. 등록보다 앞에 둔다.

할 일:

- `users.php`, `auth.php`, `csrf.php`를 만든다.
- `register.php`, `login.php`, `logout.php`를 만든다.
- 헤더를 세션에 맞게 바꾼다.
- 가입, 로그인, 로그아웃에 CSRF를 처음부터 넣는다.
- 비밀번호 해시는 `password_hash`만 사용한다.

완료 조건:

- T01, T02, T03, T04, T05의 회원가입·로그인·로그아웃 부분이 기대와 같다.
- 브라우저를 닫기 전에는 페이지를 옮겨도 로그인이 유지된다.
- 로그아웃 GET은 세션을 지우지 않는다.

### 7단계. 등록, 수정, 삭제

필수.

할 일:

- `validateItemInput()`, `createItem()`, `updateItem()`, `deleteItem()`을 구현한다.
- 세 진입 파일을 만들고, 모두 `requireLogin()`과 CSRF를 적용한다.
- 삭제 GET은 확인만 한다.
- 등록 직후 상태를 `ON_SALE`로 고정한다.
- 수정·삭제의 WHERE에 세션 사용자와 `ON_SALE`을 넣는다.
- `my-items.php`와 `listItemsByUser()`를 만들고 헤더에 링크를 둔다. 정렬 선택과 페이지네이션은 넣지 않는다.

완료 조건:

- A가 상품을 등록하면 상세로 이동하고 판매자가 A다.
- A가 자신의 판매 중 상품을 수정하고 삭제할 수 있다.
- 비로그인 등록이 저장되지 않는다.
- 음수 가격과 빈 이름이 저장되지 않는다.
- 확인 화면 GET만으로는 행이 지워지지 않는다.
- 로그인한 사용자는 내 판매 목록에서 자신의 상품만 본다.

### 8단계. 인증과 권한 검사 마무리

필수.

할 일:

- 상세에서 작성자이고 `ON_SALE`일 때만 수정·삭제 링크를 출력한다.
- 타인 id, 없는 id, 진행 중·완료 상품의 수정·삭제를 7단계 규칙과 맞춰 확인한다.
- 폼 hidden에 `user_id`가 없는지 본다.

완료 조건:

- T14, T15, T16, T24가 기대와 같다.
- 링크를 숨긴 뒤에도 POST를 직접 보내면 403이다.

### 9단계. 검색과 게임 필터

필수.

할 일:

완료 조건:

## 3. README에 넣을 내용

README는 구현과 테스트가 끝난 뒤에 작성한다. 설계 단계에서 README 파일을 만들지 않는다.

문장 규칙:

- 확인한 버전, 실행한 테스트, 만든 화면만 완료형으로 쓴다.
- 설계만 된 기능은 "이번 범위에 넣지 않음" 또는 "이후 개선"으로 쓴다.
- 샘플 계정은 샘플이라고 적는다. 운영용 비밀번호처럼 보이지 않게 한다.
- 특정 상용 서비스의 이름과 화면을 베낀 설명은 넣지 않는다. "게임 아이템 판매 정보를 등록하고 조회하는 PHP 연습 프로젝트"로 소개한다.

### 3.1 절 구성

| 절 | 필수 여부 | 적을 내용 |
| --- | --- | --- |
| 프로젝트 소개 | 필수 | 한 단락. 판매 정보 등록과 조회, 상태 표시까지. 결제는 하지 않는다는 사실 |
| 개발 목적 | 필수 | PHP, PDO, 세션, MySQL을 프레임워크 없이 사용했다는 학습 목적 |
| 기술 스택 | 필수 | 실제로 사용한 PHP 버전, MariaDB 또는 MySQL 버전, Apache, HTML, CSS, PDO |
| 주요 기능 | 필수 | P0에서 동작이 확인된 기능만 목록으로. P1은 구현·테스트가 끝난 것만 이 목록에 넣음 |
| 개발 환경 | 필수 | macOS, XAMPP, 확인한 버전, DocumentRoot가 `public`인 점, 로컬 HTTP라 세션 쿠키 `Secure`를 쓰지 않은 점 |
| 데이터베이스 구조 | 필수 | 테이블 이름과 관계 요약. 상세는 `docs/database-design.md`로 연결. 스키마 파일 경로 |
| 실행 방법 | 필수 | DB 생성, 계정, `config.example.php` 복사, 스키마와 시드 적용, Apache 경로, 접속 URL. 실제 비밀번호 값 대신 "로컬에서 정한 값"이라고 적음 |
| 주요 화면 | 선택 | 직접 캡처한 목록, 상세, 등록, 로그인. 캡처하지 않았으면 절을 비우거나 생략 |
| 보안 처리 | 필수 | 적용한 항목만. prepared statement, 비밀번호 해시, 출력 이스케이프, CSRF, 세션, 작성자 검사, GET 변경 금지, 오류 숨김, 설정 파일 분리 |
| 테스트 결과 | 필수 | T01~T29 표. 실행하지 않은 행은 미실시. 실패를 통과로 고치지 않음 |
| 구현하면서 고려한 사항 | 필수 | 게임·서버 마스터 데이터, 상태 전이, 등록보다 로그인을 먼저 구현한 이유, 결제와 구매자 기능을 두지 않은 이유 |
| 이후 개선 | 필수 | 구현하지 않은 P1, 그리고 P2는 범위 밖이라는 구분. 이메일 인증이나 결제를 한 것처럼 적지 않음 |

### 3.2 테스트 결과 예시 형식

구현 전에 숫자를 채우지 않는다.

```text
| ID | 결과 | 실행일 | 비고 |
| T01 | 미실시 |  |  |
```

실행 후에는 `통과` 또는 `실패`와 실제 날짜만 허용한다.

### 3.3 README에 쓰지 않을 것

- 결제, 정산, 채팅, 이미지 업로드를 지원한다는 문장
- 실행하지 않은 테스트의 통과율
- 운영 서버에 배포했다는 내용. 배포하지 않은 경우
- `config.php`의 실제 비밀번호
- 설계 문서의 미확정 사항을 이미 사용자가 확정한 것처럼 바꾸는 내용

| 10 | `item-status.php`, 전이 함수 |
| 14 | `my-items.php` |
| 17 | `README.md` |

5단계 전에 상품 변경 함수를 만들지 않는다. 6단계 전에 등록 POST를 열지 않는다.

## 5. 한 번에 확인하는 P0 시연 순서

12단계 완료 판단에 같은 순서를 사용한다.

1. 비로그인으로 목록과 상세를 본다.
2. 게임 필터와 이름 검색을 한다.
3. 회원가입하면 로그인된 채로 목록이 열린다. 로그아웃 후 다시 로그인한다.
4. 상품을 등록하고 상세에서 가격을 수정한다.
5. 판매 중에서 거래 진행 중, 거래 완료로 바꾼다.
6. 다른 계정을 만들어 첫 계정의 상품 수정과 삭제가 거절되는지 본다.
7. 자기 판매 중 상품을 삭제한다.
8. 로그아웃 후 등록 주소가 막히는지 본다.
